# ออกแบบระบบจัดการใบรับรองการหักภาษี

## เป้าหมาย

เพิ่มหน้าจัดการข้อมูลในตาราง `data_tax` ที่เป็นแหล่งข้อมูลเดียวกับหน้า
`/tax-certificate` เพื่อให้ผู้ดูแลนำเข้าไฟล์ TXT จากกรมบัญชีกลาง,
ค้นหา และแก้ไขข้อมูลใบรับรองรายบุคคลได้อย่างปลอดภัย

## ขอบเขตและสิทธิ์

- เพิ่มหน้า `/admin/tax-certificates` และเมนู “จัดการใบรับรองภาษี” ในกลุ่มเมนูผู้ดูแล
- อนุญาตเฉพาะบทบาท `ADMIN` และ `FINANCE`; บทบาทอื่นต้องได้รับ HTTP 403
- คงหน้า `/tax-certificate` สำหรับผู้ใช้ทั่วไปไว้เหมือนเดิม และให้อ่านจาก
  `data_tax` ชุดเดียวกับหน้าจัดการ
- เมื่อมีข้อมูลจากไฟล์ ให้ preview/PDF แสดงข้อมูลผู้จ่ายเงิน ผู้ถูกหักภาษี
  ประเภทแบบ และวิธีจ่ายจาก record นั้น โดยคง A4 layout เดิมไว้
- กล่องเพิ่ม แก้ไข ลบ และยืนยันนำเข้าใช้ application modal; การสำเร็จแสดง
  toast และคงอยู่หน้าเดิม

## โมเดลข้อมูล

ตารางเดิม `data_tax` ใช้คีย์หลักร่วม `(cid, income_year)` อยู่แล้ว จึงไม่มี
migration ใหม่ในขอบเขตนี้ โดยหนึ่งรายการหมายถึงใบรับรองหนึ่งใบของบุคลากร
หนึ่งคนในปีภาษีหนึ่งปี

การแก้ไขหรือการนำเข้าจะเขียนฟิลด์เดิมทั้งหมดที่แบบฟอร์มใช้ เช่น ข้อมูล
ผู้จ่ายเงิน ผู้ถูกหักภาษี ประเภท ภ.ง.ด. ยอดเงิน ภาษี กองทุน รูปแบบการจ่าย
และ `date_report`; ตั้ง `r_update` เป็นเวลาปัจจุบัน

## หน้าจัดการ

หน้า Livewire ใหม่จะแสดง:

1. ตัวกรองปีภาษี, CID และชื่อ-นามสกุล พร้อม pagination
2. ตารางรายการที่มีเลขที่ใบรับรอง, ผู้ถูกหักภาษี, เงินได้, ภาษีหัก ณ ที่จ่าย,
   กองทุน และวันออกเอกสาร
3. ปุ่มเพิ่ม แก้ไข และลบ โดยใช้ `(cid, income_year)` เป็นตัวระบุรายการ
4. ส่วนอัปโหลด TXT ที่เลือกไฟล์ก่อน แล้วเปิด modal ยืนยันก่อนสั่งนำเข้า
5. สรุปผลหลังนำเข้า: อ่านได้, เพิ่มใหม่, ปรับปรุง, ข้าม และผิดพลาด พร้อม
   ข้อผิดพลาดตามเลขบรรทัดโดยไม่แสดง CID เต็มจำนวน

## การนำเข้า TXT

`TaxCertificateTxtImportService` รับไฟล์ `.txt` ที่ขนาดไม่เกิน 5MB,
อ่านจาก temporary upload โดยไม่เก็บไฟล์ต้นฉบับถาวร และรองรับทั้ง UTF-8 กับ
TIS-620 โดยแปลงเป็น UTF-8 ก่อนแยกแถวด้วย `fgetcsv(..., '$')`.

แต่ละแถวต้องมี 20 คอลัมน์ตามไฟล์กรมบัญชีกลาง:

| ดัชนี | ข้อมูล |
| --- | --- |
| 0-3 | เลขที่/ชื่อ/เลขผู้เสียภาษี/ที่อยู่ผู้จ่ายเงิน |
| 4-8 | CID, เลขผู้เสียภาษี, ชื่อ, ที่อยู่ และลำดับผู้ถูกหัก |
| 9-10 | รหัส ภ.ง.ด. และปีภาษี พ.ศ. |
| 11-15 | เงินได้, ภาษี, ยอดรวม, ภาษีรวม และภาษีตัวอักษร |
| 16-17 | ประเภทและยอดกองทุน |
| 18-19 | วิธีออกหนังสือรับรอง และวันออกแบบ `DDMMYYYY` พ.ศ. |

กติกาแปลงข้อมูล:

- CID ต้องเป็นตัวเลข 13 หลัก มิฉะนั้นข้ามแถวและรายงานเหตุผล
- ยอดเลขจำนวนเต็มแบบ fixed-width แปลงจาก 2 หลักท้ายเป็นทศนิยม เช่น
  `000003155000` เป็น `31550.00`; ค่าว่างหรือศูนย์ล้วนเป็น `null`
- รหัสประเภท ภ.ง.ด. 1–7, กองทุน 1–2 และวิธีจ่าย 1–4 แปลงเป็นชื่อภาษาไทย
  ตาม mapping ในตัวอย่าง; รหัสนอกกลุ่มเป็นข้อผิดพลาด
- วันที่ต้องเป็น `DDMMYYYY` ของปี พ.ศ.; วันที่ไม่ถูกต้องเป็นข้อผิดพลาด
- เก็บ `income_year` และ `date_report` เป็นปี พ.ศ. ตามไฟล์ เพื่อให้หน้า
  `/tax-certificate` เลือกปีได้ตรงกับข้อมูลเดิม

## การเขียนข้อมูลและความปลอดภัย

- ใช้ transaction และ Laravel query builder/Eloquent parameter binding เท่านั้น
- upsert ด้วยคีย์ `(cid, income_year)` ตามพฤติกรรม `REPLACE` เดิม:
  หากมีอยู่ปรับปรุง หากไม่มีเพิ่มใหม่; ไม่ลบข้อมูลของปีหรือบุคลากรที่ไม่มีในไฟล์
- validate นามสกุล, MIME ที่อนุญาต และขนาดไฟล์; ไม่อ่านไฟล์เป็น SQL และไม่ log
  เนื้อหาไฟล์, CID เต็ม, หรือข้อมูลภาษีรายบุคคล
- หน้ารายการค้นหาได้เฉพาะบทบาทที่ได้รับสิทธิ์ และไม่เพิ่ม endpoint สาธารณะ

## การทดสอบและการยืนยันผล

- Unit tests: การแปลง TIS-620, delimiter `$`, money fixed-width, date พ.ศ.,
  mapping รหัส, แถวขาดคอลัมน์ และ CID ไม่ถูกต้อง
- Feature tests: upsert เพิ่ม/ปรับปรุงโดยไม่ลบข้อมูลที่ไม่อยู่ในไฟล์,
  role authorization, การเพิ่ม/แก้ไข/ลบ, และการสรุปผลนำเข้า
- ตรวจว่า `/tax-certificate` อ่านรายการที่นำเข้าได้ของผู้ใช้ที่ CID ตรงกัน
- รัน focused tests, `php artisan test`, `php artisan route:list` และ
  `npm run build` ก่อนส่งมอบ

## นอกขอบเขต

- ไม่เปลี่ยนรูปแบบ A4/เส้น/ตำแหน่งของ PDF หรือ preview ใบรับรองเดิม
- ไม่สร้างตารางใหม่สำหรับประวัติการนำเข้าในรอบนี้
- ไม่ลบหรือ replace ข้อมูลทั้งปีจากการนำเข้าไฟล์หนึ่งครั้ง
